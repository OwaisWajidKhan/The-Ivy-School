## Git workflow (IMPORTANT — always branch, merge via PR)
- **Never commit directly to `main`.** `main` must stay in sync with `origin/main` and only change via a reviewed pull request.
- For every feature or bug fix, create a dedicated branch off the latest `main`:
  ```powershell
  git checkout main
  git pull            # ensure up to date
  git checkout -b feat/<short-description>      # or fix/<short-description>
  ```
- Commit your work on the branch with a concise message, then push:
  ```powershell
  git push -u origin feat/<short-description>
  ```
- Open a pull request into `main` (via `gh pr create` or the GitHub web UI), get it reviewed, then **merge through the PR** (prefer "Squash and merge"). After merge, clean up:
  ```powershell
  git checkout main
  git pull
  git branch -d feat/<short-description>
  ```
- Keep the working tree clean on `main`: never leave uncommitted changes or stray test artifacts (`test.db`, `test-turso.db`, `data/*.db`) in the repo.

## Known issues / gotchas
- **NEVER run `Stop-Process -Name node -Force`** — it kills ALL node processes on the machine (including the assistant tooling) and can hang the session. To restart only the backend, stop the specific process holding port 5000:
  ```powershell
  $pidToKill = (Get-NetTCPConnection -LocalPort 5000 -State Listen).OwningProcess
  Stop-Process -Id $pidToKill -Force
  ```
  Prefer running the backend with `node --watch src/index.js` so code edits auto-reload (no manual restart needed).
- Re-seeding: delete `backend/data/school.db*` (db + -wal + -shm) BEFORE `npm.cmd run seed`, else old rows persist. The running server holds an open DB handle — stop it first (see above) before re-seeding on Windows.
- `attendance_logs.person_id = 0` is used as a sentinel for unknown-card scans (no FK). Filter `person_id > 0` in any report that joins people.
- Attendance "today" seed only writes IN scans (no OUT) so the live dashboard looks in-progress; OUT is closed on the next scan.
